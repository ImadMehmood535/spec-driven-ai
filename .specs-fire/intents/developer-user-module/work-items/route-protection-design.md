# Design: Route Authentication and Authorization Guards

> Checkpoint 1 self-served under the standing instruction.

## Summary

Apply the module's own RBAC to its own endpoints. Satisfies FR-AC5–FR-AC7 and D-7: every route
except login requires a valid JWT, and each management route requires the permission governing
it.

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Authentication | Global `JwtAuthGuard`, opt out with `@Public()` | A global guard with explicit exemptions fails closed; per-route opt-in fails open the moment someone forgets |
| Authorization | Global `PermissionsGuard` reading `@RequiresPermission()` | Same posture |
| **Default deny** | A route with **no** declared permission and no `@Public()` is **refused (403)** | An omission must fail closed. This is the single most important decision here |
| Permission source | **The JWT claims** | Consistent with D-2, and avoids a database round trip per request. Consequence: a revocation takes effect on token reissue, not immediately — stated plainly below |
| Public routes | `POST /auth/login`, `GET /health`, Swagger | Login cannot require a token; health and docs are not access-controlled |
| 401 vs 403 | Distinct (FR-AC7) | "Not authenticated" and "not permitted" are different answers a client must handle differently |
| Guard location | `api/guards/` | Coding standards: no permission logic in a handler |

## The staleness trade-off, stated

Reading permissions from claims means a permission revoked at 10:00 still works until the
token expires (default 1h). The alternative — a live resolution query per request — would make
revocation immediate at the cost of a query on every call, and would contradict D-2's stateless
design.

Choosing claims is therefore a deliberate acceptance: **revocation is not immediate.** Anything
needing immediacy must call `GET /user/:id/permission`, which is uncached by design. Shortening
`JWT_EXPIRES_IN` narrows the window.

## Technical Approach

```
APP_GUARD: JwtAuthGuard      → verifies the bearer token, attaches claims to the request
APP_GUARD: PermissionsGuard  → reads @RequiresPermission(), checks the claims

@Public()                          → skips both
@RequiresPermission('user.create') → requires that name in the claims
(neither)                          → 403, default deny
```

Route → permission mapping uses the names `seed-bootstrap` created, so an administrator can
actually reach everything.

## Security Considerations

- **Default deny.** A new route added without a decorator is refused, not exposed.
- **Distinct 401/403.** A missing/invalid token is 401; a valid identity without the permission
  is 403.
- **Malformed and expired tokens** are 401, with no detail leaked about why.
- **The guards do not reimplement resolution.** They read claims derived from the shared query,
  so FR-AC3's gates cannot drift between login and enforcement.
- **The UI is not the boundary.** FR-UI6 hides controls; enforcement is here.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| A route left undecorated and silently public | Unauthenticated access to management data | Default deny + a test asserting an undecorated route is refused |
| Guards reimplementing resolution and drifting | Enforcement disagreeing with what login granted | Guards read claims only |
| A permission name required but never seeded | Administrator locked out with no way to grant it | Names come from the seeded catalogue; a test cross-checks |
| Locking out the seeded administrator | Nobody can administer anything | End-to-end test: admin logs in and reaches every route |
| 401 and 403 conflated | Clients cannot distinguish re-login from insufficient rights | Separate errors, separate tests |

## Implementation Checklist

- [ ] `@Public()` and `@RequiresPermission()` decorators
- [ ] `JwtAuthGuard` (verify, attach claims, 401 on absent/malformed/expired)
- [ ] `PermissionsGuard` (default deny; 403 when the claim is missing)
- [ ] Both registered as `APP_GUARD`
- [ ] Every route annotated; login/health/docs public
- [ ] Tests for each guard branch, plus default deny
- [ ] Live: admin reaches every route; a limited user gets 403; no token gets 401
