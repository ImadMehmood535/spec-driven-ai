# Design: Seeds — Permissions, Admin Role, First Administrator

> Checkpoint 1 self-served under the standing instruction.

## Summary

Idempotent seeds that make the system usable from a cold start: the permission catalogue, an
administrator role holding **every** permission, and the first administrator. Satisfies
FR-S1–FR-S7 and resolves the §2 bootstrap problem — an "authorized administrator" must exist
before any endpoint can be called.

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Tooling | `sequelize-cli` seeders, separate from migrations (FR-S5) | Recorded in `tech-stack.md`; schema and data have different lifecycles |
| Idempotency key | Natural keys — permission `name`, role `name`, user `email` | Ids differ between environments; names do not |
| Admin credentials | Environment only; **seed fails loudly if absent** | A default admin password is a backdoor in every environment that forgot to set one |
| Existing admin | Password **never** reset on re-run (FR-S4) | Re-running a seed must not silently change a live credential |
| Admin grants | Every permission in the table, computed at run time | FR-S7. Computing it means a later permission is picked up on the next run, rather than the list going stale |
| Module permission names | `resource.action`, matching §5's shape | FR-S6; `route-protection` requires these names |
| Reactivation | A previously deactivated seeded row is reactivated | Otherwise a deactivated `project.view` would stay dead after a re-seed |

## The permission catalogue (FR-S1, FR-S6)

**From `docs/scope.md` §5** — actions belonging to other modules:
`project.create`, `project.update`, `project.delete`, `project.view`

**This module's own** — the names `route-protection` will require on its routes:
`user.create`, `user.view`, `user.update`, `user.assign-role`, `user.change-password`,
`role.create`, `role.view`, `role.update`,
`permission.create`, `permission.view`, `permission.update`,
`role-permission.view`, `role-permission.assign`, `role-permission.remove`

Activate/deactivate rides on `update` because that is how the routes work — inventing a separate
`*.activate` permission would describe an API that does not exist.

## Technical Approach

```
20260912200000-seed-permissions.cjs      upsert by name, reactivate if inactive
20260912200100-seed-admin-role.cjs       upsert by name
20260912200200-seed-admin-links.cjs      link admin role to EVERY permission (computed)
20260912200300-seed-first-admin.cjs      upsert by email; NEVER touch an existing password
```

Four seeders rather than one, so a failure is attributable and each is independently re-runnable.
Ordering is by filename, matching the FK dependencies.

## Security Considerations

- **No default credentials.** `SEED_ADMIN_EMAIL`, `SEED_ADMIN_USERNAME`, `SEED_ADMIN_PASSWORD`
  are all required; the seeder throws with a clear message if any is missing.
- **The password is hashed** through the same `bcrypt` cost 12 used by the application.
- **Re-running never resets an existing administrator's password**, so a seed cannot be used to
  take over a live account.
- **The admin genuinely holds everything**, verified by resolving its permissions through the
  real resolution query and comparing against the permission table — not by trusting the insert
  list.
- **No plaintext in the repository.** The seeder reads the environment; `.env` is git-ignored.

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Admin missing a permission added later | Administrator locked out of new routes | Links computed from the table at run time; a re-run grants newly added permissions |
| Re-run resetting a live admin password | Account takeover via a routine deploy | Explicitly skips the password for an existing user; test asserts the hash is unchanged |
| Default password shipped | Backdoor | Seeder throws when any admin variable is absent |
| Duplicate rows on re-run | Broken uniqueness, confusing data | Upsert by natural key; a re-run test asserts counts are unchanged |
| A deactivated seeded row staying dead | Seed appears to do nothing | Reactivates inactive seeded rows |

## Implementation Checklist

- [ ] A shared `seed-catalogue.cjs` listing every permission name once
- [ ] Four seeders, ordered, each idempotent
- [ ] `npm run seed` and `seed:undo`
- [ ] Fails loudly without the admin environment variables
- [ ] Live: first run creates; second run changes nothing; admin resolves to the full set
- [ ] Live: admin can log in with the configured password
