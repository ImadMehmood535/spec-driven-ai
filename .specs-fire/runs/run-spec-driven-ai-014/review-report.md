## Review of the details

**Create and edit share one form.** Two forms differing only in a submit handler is the
duplication this project keeps forbidding, and a test asserts both modes come from the same
component.

**Field errors and toasts are used for different things.** A conflict on the name shows on the
input, where the user can fix it. A failure with no attributable field becomes a toast. A test
asserts the conflict path does not merely toast.

**Deactivation copy says what changes**: "will stop granting access immediately, for every role
that holds it." D-5 makes deactivation the only retirement mechanism, so the dialog carries the
weight a delete dialog normally would — and it is honest about the blast radius.

**No delete, asserted rather than omitted.** The test enumerates the row menu and expects exactly
`Edit` and `Deactivate`. An omission can be re-added by accident; a test cannot.

**Gating uses the names the seed creates** — `permission.create`, `permission.update`. If they
did not exist, an administrator could not be granted them (run 009's cross-check covers the
backend side).

## Observations — no action taken

**`api-error.ts`'s prose matching has a demonstrated limit.** Its own review note in run 011 said
it was fragile if the API's wording changed; this run found the adjacent case — wording that
never contained the field name at all. The pattern that emerged is sound: generic inference as a
fallback, with a form overriding when it knows its domain. The roles and users screens should
follow it.

**Sorting is disabled on every column.** The API accepts no sort parameter for permissions, so
offering a sort control that did nothing would be worse than not offering one. If sorting is
added to the API, `enableSorting` and an `onSortingChange` handler are the only changes needed.

**The list invalidates on every mutation**, so the table reflects the server rather than a local
guess. Slightly more network for correctness that is hard to get wrong.

**Interaction tests are slow** (~47s for the page suite) because each opens a Radix menu or
dialog. Known from run 012; not a defect in these tests.
