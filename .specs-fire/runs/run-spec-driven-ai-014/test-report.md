## The one real defect found, and it was a product gap

A test asserting the duplicate-name conflict landed on the `name` input **failed**. The cause
was not the test: the API's message is `Permission "project.create" already exists.`, which never
contains the word "name", so the generic inference in `api-error.ts` returned `undefined` and the
error rendered detached from the input.

FR-UI9 requires server field errors to map back onto the right field, so the fix went into the
product, not the test: a conflict on this form can only concern the name — it is the only unique
field — so the form attributes it. The generic inference stays as a fallback.

Worth recording that `api-error.ts`'s prose-matching has a real limit, exactly as its own review
note predicted. Where a form knows its domain, the form should decide.
