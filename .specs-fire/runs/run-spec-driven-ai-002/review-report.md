## Observations — no action taken

**Migrations are `.cjs`, outside the TS build.** Deliberate, per the design: `sequelize-cli`
runs them with node. They are therefore not type-checked or linted — the schema contract test
is what catches drift between them and the models.

**`dotenv` added as a runtime dependency.** `src/config/database.cjs` needs it because the CLI
boots outside Nest and so has no `ConfigModule`. The app itself still reads config through
Nest. Two loaders for one `.env` file is slightly redundant but unavoidable while the CLI is the
migration tool.

**`RolePermissionModel` declares the composite unique as a model-level index.** Sequelize needs
it there rather than on a column. It duplicates what the migration created — intentionally, so
the contract test can assert it, but it is a place where model and migration must be kept in
step by hand.

**No `updatedAt` anywhere.** `modifiedOn` plus `timestamps: false` is the reference convention;
Sequelize's own timestamp handling stays off.
