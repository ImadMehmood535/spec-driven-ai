## Details worth recording

**The table distinguishes "no matches" from "nothing exists yet".** Telling a user to "create
your first record" when they have simply typed a filter that matches nothing is misleading, so
`isFiltered` switches the empty copy and drops the create action.

**State precedence is asserted**, not assumed: error beats loading beats empty. A test supplies
an error alongside empty data and expects the error.

**Sorting cycles ascending → descending → none**, with `aria-sort` on the column header, and a
column marked `enableSorting: false` renders no sort control.

### A change I made and then reverted

I wrapped `userEvent.setup` to pass `delay: null`, on the theory that its simulated pointer delay
was what made the menu test slow. Measured: 7.5s → 7.4s. The theory was wrong, so the wrapper
went back out rather than staying with a comment claiming a benefit it does not deliver.

The real cause is Radix's own behaviour under jsdom. The raised timeout handles it; the
interaction is genuinely slow to simulate, not incorrectly written.
