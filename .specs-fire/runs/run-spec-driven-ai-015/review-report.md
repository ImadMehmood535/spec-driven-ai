## Review of the assignment view — the new work here

**Already-assigned permissions are filtered out of the available list.** That makes the 409 path
unreachable through normal use, which is the right UX: offering something that will be rejected
is a trap. A 409 is still handled, because a second administrator could assign concurrently —
the conflict surfaces as a toast rather than a crash.

**Only active permissions are offered.** Assigning a deactivated permission would grant nothing
(FR-AC3), so offering it would be misleading. The catalogue query filters on `entityStatus`.

**Removal copy reflects D-8.** It says the permission will no longer apply and can be assigned
again — not that it is deleted. And there is **no reactivate control**, because re-adding is an
ordinary assign; the backend reactivates the same row. Inventing a separate control would have
exposed an implementation detail as a user-facing concept.

**The deactivation dialog carries information the screen cannot show.** A role's table row says
nothing about FR-AC3, so the confirmation says it: users keep the role and gain nothing from it.

**Both halves of the dialog have their own states.** Assigned has loading, empty and error;
available has loading and two distinct empty messages — "no matches for that search" versus
"everything active is already assigned". Conflating those would mislead.

## Observations — no action taken

**The available list caps at 50 permissions.** Fine for a catalogue of 18 and for search-driven
selection; a catalogue in the hundreds would want the search to drive server-side paging rather
than filtering one page. The search already goes to the server, so the change would be small.

**Assignment sends one permission at a time**, though the API accepts an array. One-at-a-time
gives immediate feedback per click and keeps the optimistic surface small. Multi-select would be
a reasonable later addition and the API already supports it.

**`RolePermissionsDialog` imports `usePermissionList` from the permissions feature.** A
cross-feature import, but the right one — the alternative is a second hook fetching the same
endpoint, which is the duplication FR-UI13 forbids.
