## On the CORS finding

This is the defect an end-to-end suite exists to find, and it is worth being precise about why
nothing earlier caught it:

- **Backend runs** verified with `curl`, which does not enforce CORS.
- **Frontend runs** verified with MSW, which intercepts before a real request leaves.
- **Runs 011–016** served both projects and checked each responded — but never made the browser
  call the API.

Every individual verification was sound. The gap was between them, which is the category of
defect integration testing is for.

The fix uses an **explicit allow-list, never a wildcard**. A test asserts that directly, because
`origin: '*'` is the reflexive fix and the wrong one for an authenticated API. `credentials` stays
`false` — the token travels in an `Authorization` header, not a cookie, so the browser is never
asked to attach anything automatically.

## Review of the suite itself

**It is deliberately small.** Nine tests against 605 unit tests. Component states, validation
messages, keyboard behaviour and axe are all covered elsewhere; repeating them here would be slow
and duplicate coverage rather than add it. These nine cover only what the other suites cannot:
the token crossing a real network, and a status change propagating through resolution to the UI.

**The management flow asserts the effect, not just the clicks.** After driving the UI it queries
the API for the user's effective permissions, then deactivates the permission and asserts the
exclusion, then reactivates and asserts restoration. That last step matters: without it, the
exclusion could be data destruction rather than the FR-AC3 gate working.

**Setup goes through the API, assertions go through the UI.** The authorization specs create
their limited user via `apiPost` rather than clicking through the admin screens — those clicks
are already tested, and re-driving them would make the spec slow and fragile for no gain.

## Observations — no action taken

**The suite requires a running API and does not start one.** Deliberate: starting the backend
from the frontend project would couple them, which the constitution forbids. The Playwright
config starts only the UI.

**Workers are set to 1.** The specs share one database and one seeded administrator; parallel
runs would interleave. Correctness over speed, and the suite takes about seven seconds.

**Every run leaves rows behind.** That is D-11's accepted cost of D-5 — nothing is deletable. A
long-lived development database will accumulate `endtoend.*` permissions and `E2E Role-*` roles.
Worth a periodic manual truncate, and the names make them easy to identify.
