# Implementation Plan: User Management Slice

> Checkpoints 1 and 2 self-served under the user's standing instruction to run the loop
> autonomously. Design doc:
> `.specs-fire/intents/developer-user-module/work-items/user-crud-design.md`

## Approach

The first slice storing credentials. Hashing happens in the application layer before the
aggregate exists, so no domain object ever holds plaintext. `UserReadModel` has no
`passwordHash` field at all — absent from the type rather than stripped at serialisation.

Six features: create, get, list, update, assign-role, change-password. Satisfies FR-U1–FR-U5
and D-9.

**Not generated by substitution**, unlike the role slice — the credential handling has no
analogue in the permission or role slices, and a plausible-looking copy would leak.

## Files to Create

`IPasswordHasher` + `BcryptPasswordHasher` (cost 12); `User` aggregate; `IUserRepository` +
`UserRepository`; `IUserQueries` + `UserQueries` (explicit attribute list, no hash);
`UserPersistenceModule`; `UserModule`; six feature folders; `UserController`; six spec files.

## Files to Modify

`api/ApiModule.ts` (register), `api/controllers/AppController.spec.ts` (stub `UserModel`, add
`/user` to the routing assertion).

## Tests

Aggregate invariants; hasher cost and salting; create (hash applied, plaintext never persisted
or returned); update (hash untouched); assign-role (**replaces**, never accumulates);
change-password (no current-password challenge, no material returned); list (no password key);
controller HTTP including **two log-redaction assertions** on the create and password routes.

Plus live verification against the real database.

## Technical Details

**Password rules**: minimum 8 characters, checked before hashing so a rejected request does
not pay for a cost-12 hash.

**Uniqueness before hashing**: email and username are checked first, for the same reason.

**The update route has no password field.** A credential arriving in a general-purpose PATCH
body is an unexpected credential in an unexpected place; `PATCH /user/:id/password` exists
instead (D-9).

**Email is lowercased** by the aggregate so uniqueness is not case-dependent —
`Ahmed@Example.COM` and `ahmed@example.com` are the same user.
