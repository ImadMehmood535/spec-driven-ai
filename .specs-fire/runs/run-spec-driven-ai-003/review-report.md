## Observations — no action taken

**Uniqueness is checked in two places, deliberately.** The handler calls `nameExists` for a
clean 409; the DB constraint is the real guarantee under a race. Mirrors the reference's
`slugExists`. A caller hitting the race gets a 500 from the constraint rather than a 409 — worth
revisiting if it ever matters, but adding transactional handling here would be speculative.

**`GetPermissionResponse.from` uses `Object.assign`.** Concise, and the read model's shape is
identical to the response. If they diverge, this needs explicit field mapping — the pattern for
the other entities should not blindly copy it where shapes differ.

**Activate/deactivate rides on `PATCH`.** FR-P4 is satisfied by a status transition. The
aggregate also exposes `activate()`/`deactivate()`, currently unused by the handler, which uses
`changeStatus`. They exist because `seed-bootstrap` and the role slice will want them; if they
stay unused after those land, they should go.

**No `findAll` on the repository.** Reads go exclusively through the query class. This is the
CQRS split working as intended and is the main thing the other three slices must copy.
